# Overview

- Goal: build an ML model to predict Brawl Stars match outcomes from brawler picks
- Input signals: event (map/mode), brawler composition per team, player trophy level as a skill proxy
- Output: win probability for a given team composition

## Layout

- `workflow/` — Snakemake pipeline; fetches raw JSON from the Brawl Stars API (`$BSTOK`) into `data/`, plus `export_onnx` (`just export-onnx`) which traces the trained checkpoints to ONNX for `web/`, and `tier_lists` / `tier_lists_optimal` (`uv run tier-list --policy random|optimal`) which Monte Carlo-sample per-map first-pick tier lists via the terminal `BrawlModel` into `data/tier_lists.json` / `data/tier_lists_optimal.json`; all rules currently pin `terminal_ckpt`/`draft_ckpt` to `data/terminal_myt2_20260916/model.eqx` and `data/draft_myt2_20260916/draft_q_best.eqx` (the dated per-dataset dirs are the live checkpoints — `data/model/` and `data/draft_model/` are stale/absent) — update the Snakefile when a newer pairing is trained
- `src/crawl/` — REST client, battle log scraper; fetches and aggregates battle data
- `src/geneus/` — ML model and training loop (`BrawlModel`, `train` CLI); `--out`, `--init-from`, and `--battles-file` are all given relative to `--data-dir` (default `data`, or pass an absolute path); `--out` names an output *directory* (default `data/model`), into which the best checkpoint is always written as `model.eqx`, periodic checkpoints as `checkpoints/model_epoch_NNNN.eqx`, and the loss/accuracy plot as `train_curves.png`; `--battles-file` selects which `crawl_*.json` to train on, `--init-from <ckpt>.eqx` warm-starts weights from an existing checkpoint onto a new dataset while always reinitializing the optimizer/LR schedule (`just train`, `just continue-training <ckpt> <battles_file>`); if the vocab has grown since the checkpoint (new brawlers/events), `--init-from` automatically extends the affected embedding tables, left-aligning the checkpoint's rows and randomly initializing the new tail rows — correct only because `load_vocabs` assigns indices by ascending raw id, so growth must never reorder or insert before an existing id (see `load_vocabs` docstring)
  - `geneus/mc.py` — domain-agnostic Monte Carlo estimation: `estimate_until_converged` repeatedly calls a caller-supplied `sample_batch(rng, batch_size) -> (candidate_idx, value)` and keeps sampling until the per-candidate running-mean ranking's Spearman correlation against the previous checkpoint (`rank_stability`) clears a threshold for several consecutive checks, or a trial cap is hit. Used by `pick/tier_list.py`'s two policies; not tier-list-specific — reusable for any "estimate the eventual value of a pre-condition via repeated sampling" problem
- `src/pick/` — interactive draft-assist REPL (`pick` CLI)
  - `fuzzy.py` — subsequence fuzzy match with shortest-name tiebreak (see `docs/misc_notes.md`)
  - `score.py` — checkpoint loading; `get_q_values` builds draft observations (non-pool brawlers marked `LOCALLY_BANNED`) and calls `DraftQNetwork`; `get_terminal_pick6_scores` vmaps BrawlModel over pick-6 candidates and returns `P(team B wins)`
  - `display.py` — columnar terminal grid with rarity-colored brawler names
  - `main.py` — full draft loop: coin flip → 3 ally bans → 3 enemy bans → picks 1–5 (live Q-value grid) → pick-6 win-probability grid (in-place, terminal model); Q-values are z-scored over the post-filter available brawlers; after pick 5 any Enter exits; `$BRAWL_FILTER` (comma-separated names) hides and `LOCALLY_BANNED`-marks non-owned brawlers; filter is toggled with `/` (works in all phases including pick-6); filter defaults per phase: OFF during bans, ON during ally picks, OFF during enemy picks
  - `tier_list.py` — `tier-list` CLI, `--policy random|optimal` (wrapped by the Snakemake `tier_lists` / `tier_lists_optimal` rules): per map, fixes each brawler in turn as the first pick (team A, seat 0; no bans) and Monte Carlo-samples the rest of the draft under one of two policies, via `geneus.mc.estimate_until_converged`:
    - `random` (`run_map_trials`/`_simulate_batch`): a random permutation of all brawlers; the first two fill the first-picking team's other two seats, the next three fill the opposing team, and *everyone else* is scored as that team's first pick against the same fixed continuation in one shot — answers "if I pick this brawler first, what's my win rate against a fully random rest-of-draft," unbiased by the real pick-order skew baked into `winrates_*.json`
    - `optimal` (`run_map_trials_optimal`/`_simulate_optimal_batch`, requires `draft_q_best.eqx`): the other five picks are drafted by the deployed `DraftQNetwork` policy instead — softmax(Q / `--eval-temp`, default 0.1) sampling for picks 2–5 (matching `geneus.draft.train.evaluate_vs_random`'s eval rollout), and the terminal `BrawlModel`'s exact argmin for team B's sixth (last) pick, since that pick has no further draft to look ahead through. No shared-continuation trick here (the optimal rest-of-draft depends on who was picked first), so each candidate gets its own simulated draft per trial — answers "if I pick this brawler first, what's my win rate against a team and opponents who draft well," always from the candidate's (team A's) perspective
  - `export_onnx.py` — `export-onnx` CLI (wrapped by the Snakemake `export_onnx` rule; run via `just export-onnx`): traces `DraftQNetwork` and `BrawlModel`'s pick-6 forward pass to static-shape ONNX graphs via `jax2onnx`, validates each against the JAX model (value + top-15 rank match), and writes `char_encs_all` (frozen per-event character encodings — internal to `BrawlModel`, not reachable via its public `__call__`) plus a `manifest.json` (shapes, event→row index, draft-state constants) into `web/static/`; both graphs are single-example (no batch dim) — the pick-6 candidate loop happens client-side, one inference call per candidate, matching the CLI's `vmap`. Also writes `web/tests/fixtures/onnx_fixture.json` (JAX-vs-ONNX numeric parity cases) and `web/tests/fixtures/logic_fixture.json` (`export_logic_fixture`: real-Python-generated cases for the pure draft-logic helpers — `_build_obs`, `_z_score_q`, `_pick6_team_split`, `_ban_excluded`, `_phase_default_filter`, `pick_annotations`, `overview_annotations` — so the TS ports in `web/src/lib/pick/` are checked against the real implementation, not just eyeballed)
- `web/` — SvelteKit site (web port of the `pick` CLI), keybind- and mobile-first; consumes the ONNX graphs and data exported by `export-onnx` from `web/static/models/` and `web/static/data/`
  - `src/lib/onnx/` — thin `onnxruntime-web` wrapper (`session.ts`) plus types for `manifest.json`/`metadata.json` (`manifest.ts`, `metadata.ts`); `runDraftQ`/`runTerminalPick6` serialize calls onto the same session (a per-session promise chain) since the wasm backend throws "Session already started" if a second `run()` lands before the first resolves — needed because `stress-test`'s concurrent simulated drafts all share the two engine sessions
  - `src/lib/pick/` — TS ports of the CLI's pure logic (`fuzzy.ts`, `obs.ts`, `phase.ts`, `annotations.ts`, `constants.ts`), each checked in `*.test.ts` against `logic_fixture.json`; `engine.ts` orchestrates the ONNX sessions into `scoreMap`/`getQValues`/`getTerminalPick6Scores` (mirrors `score.py`); `draftState.svelte.ts` is the Svelte 5 runes state machine mirroring `_run_draft`'s phase progression (map select → coin flip → bans → picks → pick-6), plus a web-only undo stack; `ownedBrawlers.ts` is the web port of `_parse_brawl_filter`/`_brawl_filter_names` (per-token match/no-match resolution instead of just a set + separate unmatched list), backed by `ownedBrawlersStore.svelte.ts`, a single `localStorage`-persisted comma-separated string (`brawl:ownedBrawlersText`) that both the `/settings` page and `draftState.filterIds` read from — the settings page is the only writer
  - `src/lib/components/` — `MapSelect`, `CoinFlip`, `Draft` (search input + live-scored `BrawlerGrid` + `DraftBoard`), `FilterPanel` (in-draft modal wrapping `OwnedBrawlersEditor`), `OwnedBrawlersEditor` (comma-separated owned-brawlers textarea with live per-token match feedback, also used standalone by `routes/settings/+page.svelte`), `Legend`
  - `src/lib/stress-test/` — `runAdversarialStressTest`: "how strong is this account, and which brawler should I get next?" Monte-Carlo-simulates full drafts (`simulate.ts`, 12 turns of `draftQ` + one terminal-model score) between the owned pool and a near-optimal adversary with the *entire* roster available — in-distribution since `draft_q_best.eqx` is trained with `pool_max` defaulting to every brawler — then reruns the same trials with each un-owned brawler added, ranking by paired win-rate delta. `trial.ts` stratifies event/first-pick deterministically over every cell instead of drawing them, so the only per-trial randomness left is near-optimal action-sampling noise (`rng.ts`'s seeded PRNG); default trials is `DEFAULT_STRATIFICATION_CYCLES` (8, empirically calibrated — see stressTest.ts) samples per cell, the point past which more trials only marginally stabilize the ranking further — the #1 pick and top/bottom-3 split are reliable there, exact tail order is not — pass a larger multiple of `2 * events.length` trials to sharpen it. `candidates.ts::rankCandidatesByWinrate` is a free (no ONNX) pre-screen ranking unowned brawlers by mean winrate z-score, used by the `/stress-test` page to default to a fast shortlist instead of sweeping the full roster. `routes/stress-test/+page.svelte` + `stressTestState.svelte.ts` are the UI: reads the owned set from `ownedBrawlersStore.svelte.ts`, lets the user pick a candidate-shortlist size and a trial-count "speed" (quick/balanced/thorough, in `DEFAULT_STRATIFICATION_CYCLES`-style cycles), shows a live progress bar off `onProgress`, and renders the baseline win rate plus a `BrawlerGrid` of candidates split by delta sign (via `StressTestResults.svelte`)
  - Filter (`$BRAWL_FILTER` in the CLI) is a model input during bans/picks (`local_pool` → `LOCALLY_BANNED`, feeding back into the Q-network) but a display-only filter of already-computed candidates during pick-6 — `draftState.svelte.ts` routes it accordingly and resets `filterOn` to the phase default on every phase transition, matching `_phase_default_filter`
  - Keybinds: `/` focuses the search box, `Enter`/`Escape`/arrow keys drive it and its suggestion list, `Backspace` on an empty box or `u` anywhere (not while typing) undoes the last ban/pick; on touch devices the box does not autofocus (tapping a grid card submits directly instead) while desktop autofocuses it — the search box itself stays available in every ban/pick phase (not just what the grid displays) since submittable brawlers and displayed brawlers diverge during the ban phases (`_ban_excluded` vs `_display_excluded`)
- `tests/` — unit tests (no network); `tests/integration/` — API client tests using mocked HTTP
- `docs/dataset_generation.md` — usage guide for the dataset scraper

## Key domain notes (see `battlelog_api_notes.md`)

- `type: "ranked"` = trophy matchmaking; `type: "soloRanked"` = true ranked (trophies field holds rank number, not trophies)
- Battle logs use `teams[][]` for 3v3 modes and `players[]` for showdown
- The `result` field is always from the perspective of the battlelog owner
